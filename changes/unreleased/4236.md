## 2026-10-25 - Bootstrap managed foreground launch supervisors (#4236)

### What changed

- `packages/coding-agent/src/internal-role.ts`: dispatch the managed-launch role before ordinary CLI initialization.

### Why

- `packages/coding-agent/src/internal-role.ts`: an inert engine shim must enter containment before it starts user code, independently of a disposable tool-child generation.

### Why an extension could not handle it

- `packages/coding-agent/src/internal-role.ts`: compiled and interpreted engine re-entry is owned by the CLI bootstrap.

### Expected merge conflict zones

- `packages/coding-agent/src/internal-role.ts`: additive internal-role dispatch.

## 2026-10-25 - Session ownership for explicit managed launches (#4236)

### What changed

- `packages/coding-agent/src/modes/rpc/tool-child/session-launch-supervisor.ts`: keep a session Job Object and nested per-launch jobs on Windows; use the owned-group ledger on POSIX; seal admission on session end and cancel only one call's launches.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`, `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-role.ts`, and `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-wire.ts`: hold user execution behind a private control pipe and preserve group cleanup after normal command completion or host loss.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`: actively terminate an unreleased inert bootstrap; after release, its owner stops containment before awaiting shim exit.

### Why

- `packages/coding-agent/src/modes/rpc/tool-child/session-launch-supervisor.ts`: managed foreground services need session ownership rather than a worker generation's cleanup lifetime.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`, `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-role.ts`, and `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-wire.ts`: post-execution PID notification cannot provide before-execution containment admission.

### Why an extension could not handle it

- `packages/coding-agent/src/modes/rpc/tool-child/session-launch-supervisor.ts`: native job handles and process-group identity belong to the runtime owner.
- `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-process.ts`, `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-role.ts`, and `packages/coding-agent/src/modes/rpc/tool-child/managed-launch-wire.ts`: the engine owns re-entry, the control pipe, and cleanup when the host disappears.

### Expected merge conflict zones

- The new managed-launch modules are fork-only. Existing raw cp/Bun/PTY launch families and breakaway flags are unchanged.
