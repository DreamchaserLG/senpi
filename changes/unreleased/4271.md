### Added
- Attach the interactive TUI to an existing RPC endpoint with `--attach <address> --session <ref>`, using authenticated local sockets or Windows named pipes. ## 2026-10-25 - Explicit RPC endpoint attachment arguments (senpi#4269)

- `packages/coding-agent/src/cli/args.ts`: exposes `--attach` and documents its required session reference.

## 2026-10-25 - Dispatch the attachment presentation before runtime creation (senpi#4269)

### What changed

- `packages/coding-agent/src/main.ts`: dispatches the explicit attachment through a lazy interactive presentation boundary.

### Why

- `packages/coding-agent/src/main.ts`: connecting, disconnecting, or failing to find a session must never initialize an in-process replacement.

### Why an extension could not handle it

- `packages/coding-agent/src/main.ts`: the CLI composition root owns mode dispatch before runtime and extension initialization.

### Expected merge conflict zones

- `packages/coding-agent/src/main.ts`: dispatch immediately after the version short circuit.

## 2026-10-25 - A record-driven RPC attachment presentation (senpi#4269)

### What changed

- `attach.ts`, `attach-client.ts`, `attach-dialogs.ts`, and `run-attached-tui.ts`: authenticate, attach, subscribe, read state and backward history, render dialogs, forward identified inputs, and release only the caller's attachment.
- `record-renderer.ts`: projects persisted entries and incremental or cumulative stream records into existing message components.

### Why

- An explicit attachment should present an existing session without owning a runtime, changing its profile, or falling back to a new local session.

### Why an extension could not handle it

- A presentation without a local session must be composed before session extensions exist.

### Expected merge conflict zones

- LOW: new presentation modules; the existing interactive runtime is unchanged.
